# Methodology v1.5 L2: Versioned Outputs and Contracts

Status: implemented for private shadow output bundles; no public alias switch

## R2 namespaces

The exporter renders the v1.5 YAML templates with `data_state=private_shadow`:

```text
derived/indexes/1.5.0-preview.1/private_shadow/{index_code}/
derived/diagnostics/1.5.0-preview.1/{index_code}/
```

An output bundle contains `summary.json`, `history.json`, `rebalances.json`, and private `contributions.json` under the index namespace. Daily quality and eligibility diagnostics are written below `derived/diagnostics/.../daily/{run_date}.json`. Every object carries schema version 2, the same series identity, and the private-shadow state.

The bundle manifest records the methodology version, engine revision, source hashes, and SHA-256/byte metadata for every output object. The manifest itself is not included in its own checksum list. The writer is idempotent and reports only changed keys.

## Private/public boundary

The output builder rejects missing or public-enabled v1.5 output configuration, path traversal, unversioned index paths, mismatched methodology identities, non-monthly collector rebalance payloads, and checksum changes. `target_size` is serialized as `null`; the output contract never maps the new uncapped series to a v1.4 `500` or `100` target.

The existing `derived/indexes/{legacy-code}` paths, `apps/web/source-data`, public aliases, and v1.4 TypeScript contracts are not modified by this work package. The v1.5 TypeScript contracts use a separate `CollectorIndexCode` union and accept only the 20 configured number-free codes.

## TypeScript validation

`apps/web/lib/collector-contracts.ts` validates the v1.5 summary, history, monthly rebalances, private diagnostics, manifest, and shared dataset identity. Fixtures and tests cover valid uncapped private output, public-alias rejection, numbered-code rejection, invalid cadence, and invalid selection ordering.
