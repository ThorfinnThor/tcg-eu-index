# Methodology v1.5 S2: Quality, Activity, and Eligibility

Status: implemented for the private shadow engine; not connected to public aliases

## Boundaries

This work package implements only the v1.5 universe decision and its private diagnostics. It does not calculate index values, assign weights, export public files, or change the active v1.4 methodology.

## Data Quality

`score_data_quality` uses the canonical v1.5 `avg30` fields without a listing-price fallback. It emits separate hard-gate inputs and the diagnostic score:

```text
data_quality_score
= 0.50 * valuation_observation_ratio
+ 0.30 * price_update_frequency
+ 0.20 * inverse_dispersion
```

The score is never named or interpreted as liquidity. A valid `price_avg` or `price_low` cannot replace a missing `avg30` observation.

## Trading Activity Proxy

`score_trading_activity_proxy` counts days where `avg1 > 0` over valid game snapshots. It excludes archive gaps and manifest entries marked `unchanged_from_previous`. It records positive days, ratio, zero days, missing days, repeated equal positive values, last positive date, and calendar days since the last signal.

The proxy remains diagnostic-only. The public Cardmarket download contains aggregate sale-price fields but no transaction count, quantity, condition, language, buyer, seller, or transaction timestamp. Consequently, the engine rejects a v1.5 configuration that attempts to make this proxy an eligibility gate.

## Collector Eligibility

`evaluate_collector_eligibility` evaluates every `(cm_product_id, variant_key)` independently and returns all variants that pass:

- the configured product universe;
- 90-day product seasoning;
- official 60-day history or explicit seven-day private-shadow history;
- valuation and reference-price observation ratios;
- suspect-zero control;
- latest positive `avg30` of at least EUR 10 for singles or EUR 30 for sealed.

The result is sorted by stable variant identity only for deterministic serialization. No price ranking, fixed target, product-level deduplication, quota, concentration cap, or shortfall fill is performed. The snapshot hash covers the calendar inputs, data state, diagnostics, exclusions, and eligible decisions.

## Real-archive calibration

The manually dispatched `cardmarket-activity-proxy-audit` workflow reads normalized history and manifests from private R2 using repository secrets. It uploads only aggregate per-game and per-universe rates as a private GitHub Actions artifact. Raw prices and product identities are not included.

The audit records positive, zero, missing, and repeated-positive `avg1` rates. Its semantic conclusion is intentionally limited: positive `avg1` is evidence of an aggregate one-day sale-price signal, not proof of transaction count, traded volume, market value, or investable liquidity.

Across singles games, positive rates range from 78.72% to 97.46%, while 79.54% to 91.12% of positive observations repeat the prior positive value. For sealed products, `avg1` is null or missing in every observation in this archive window.

This evidence rejects `avg1` as a hard eligibility or liquidity gate. It is too broadly positive and frequently repeated for singles, and it would exclude the entire sealed universe because the source does not populate the field there. The v1.5 engine therefore retains it only as a labeled Trading Activity Proxy diagnostic. Canonical eligibility and valuation continue to use `avg30`.
