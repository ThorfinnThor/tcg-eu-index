# Methodology v1.5 S3: Weighting and Missing Data

Status: implemented for the private collector engine; not connected to public outputs or aliases

## Isolation from v1.4

The schema-v2 collector calculation lives in `indexengine.collector_calc`. The legacy `calculate_chain_linked` path remains unchanged so v1.4 Top-500 and Top-100 series stay reproducible.

## Rebalance schedule

`build_monthly_collector_rebalances` connects the S2 eligibility result to a frozen S3 composition.

- The first private-shadow basket may start once seven prior observable source days exist. If that evaluation is empty, daily private evaluations continue until the first non-empty basket; only then does monthly membership freezing begin.
- Its `selection_as_of` is the last observable source day before the effective date.
- Every later composition becomes effective on the first observable source day of its calendar month.
- Official calculations use the first observable source day for every monthly evaluation.
- Membership and the frozen selection prices come directly from the deterministic S2 eligibility snapshot.

An empty eligible result is retained as an explicit `empty_eligible_universe` rebalance. It does not create an index value.

## Weight and value timeline

The first non-empty effective date starts at the configured base value of 1000. Constituents initialize at equal weights and no pre-inception return is attributed to that date.

At every later monthly rebalance, target weights reset to `1 / N` before the effective-date calculation. The frozen `selection_as_of` `avg30` is the prior valuation for every new basket member, so the effective-date return is measured consistently from the selection cut-off. New and returning variants cannot inherit a price from an older membership interval.

Between rebalances, the engine uses prior-day drifted weights:

```text
R(t) = sum_i [w(i,t-1) * r_used(i,t)]
Index(t) = Index(t-1) * (1 + R(t))
w(i,t) = w(i,t-1) * (1 + r_used(i,t)) / (1 + R(t))
```

Every contribution record retains target weight when applicable, weight before return, raw return, used return, contribution, and end weight. The engine asserts that end weights sum to one.

## Caps, carry, and suspension

Only positive finite `avg30` values are accepted. `price_avg` and `price_low` are ignored even when present.

- Raw constituent returns are clipped to `[-0.25, 0.25]`.
- Missing `avg30` is carried with zero return through calendar-day age five.
- From age six onward, the constituent is `suspended_stale` with zero return.
- Carried and suspended constituents retain their full prior weight and remain in the daily denominator.
- A fresh price after carry or suspension is compared with the retained last valid valuation and is subject to the same cap.
- A manifest-marked unchanged whole-market snapshot has zero return and does not reset last-valid-price dates. Already suspended constituents remain suspended.

Daily diagnostics expose capped, carried, and suspended counts and prior-weight shares, the largest end weight, the active rebalance and selection dates, and the whole-market carry flag. There is no availability-based renormalization.

## Golden calculations

The independent fixture in `tests/test_collector_calc.py` verifies:

- equal target weights followed by two-way performance drift;
- exact chain-link continuity;
- positive and negative component caps;
- calendar-day carry and suspension without weight redistribution;
- resumption from the retained valuation;
- monthly equal-weight reset with membership replacement;
- separate foil and nonfoil identities for one Cardmarket product;
- `avg30`-only valuation despite populated listing-price fields;
- unchanged-source snapshots and empty-universe reporting;
- first-shadow and later monthly calendar scheduling.
